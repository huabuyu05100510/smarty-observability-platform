# smarty-observability-platform · 专利与简历亮点

> 14 年前端专家"代表作"的核心独创点（可写简历 / 可报专利）
>
> 区分：移植自 monitor-sdk 的成熟能力（reporter 离线重试、request 监控、PII、采样、sourcemap、session-replay）**不是亮点**，是完整度底座。下列 5 项是 monitor-sdk / 业界**没有**的独创机制，是真正的差异化与可专利点。

---

## 亮点 1 ★ 注入前反事实对抗验证的 AI 自愈闭环（最强专利点）

**简历一句话**：设计"诊断→★对抗证伪→注入→回归→信心门禁"的自愈闭环，在 AI 改代码**之前**插入独立 Verifier agent 用反事实推理主动证伪根因，把 LLM-RCA 头号失败模式（幻觉类比/编造证据）拦截在行动前。

**专利结构**
- **背景/痛点**：AI 自动修 bug 假阳性高（SWE-bench Verified ~24%，UTBoost 实测 15.7% 通过原测试的补丁在增强测试上失败）。根因之一是 LLM 会"编造证据/幻觉类比"得出看似合理的错误根因。
- **现有技术不足**：业界 AI 修复（Sentry Seer、SWE-agent、Devin、sentinel-x）的验证都是**注入后回归确认式**（confirm-style）——先改、再跑测试看对不对。这只能发现"改了没用"，无法在**行动前**识别"诊断本身就是幻觉"。
- **本发明方案**：在【诊断】与【注入】之间插入一个独立的 **Verifier agent**，其 prompt 定位为"怀疑者/证伪者"（与 Diagnoser 的"生成者"对立），执行**反事实推理**："若此为真因，症状是否会精确如此呈现？引用的证据是否真实存在于栈/代码中？是否存在同样契合的替代根因？" **举证责任倒置**——支持不强则默认否决；否决则把替代假设回喂 Diagnoser 重新诊断，**先不注入**。可选多 Verifier 投票（多数否决才否决）。
- **有益效果/量化**：对标 2026 图拓扑+多 agent+反事实对抗验证 SOTA（F1 88.4%，ScienceDirect S1546221826005011）；拦截 LLM-RCA #1 失败模式（RF-01 fabricated evidence，Waterloo 48K 实证）；与"注入后回归"形成**双层护栏**（逻辑层+经验层）。
- **权利要求要点**：① 诊断与行动之间的独立对抗验证阶段；② 证伪导向 prompt + 反事实推理 + 举证责任倒置；③ 否决→替代假设回喂重诊断的控制流；④ 多 Verifier 投票机制。

## 亮点 2 ★ 确定性凌驾 AI 的信心分层门禁（Deterministic-over-AI Gate）

**简历一句话**：提出"AI 只做语义、确定性规则做最终门禁"的混合范式——一个确定性门禁叠在 AI 输出之上做自动应用决策，回归失败或 Verifier 否决时**硬阻断**（永不自动应用）。

**专利结构**
- **背景**：LLM 幻觉，用 AI 做最终放行决策不安全；但纯规则又做不了语义 RCA。
- **现有不足**：业界"信心分"多由 LLM 自报或单一阈值，AI 既诊断又放行，幻觉直通合入。
- **本方案**：分层——L4 确定性规则（变更关联/拓扑/火焰图）+ AI（LLM-RCA/Verifier）并列产出候选；L6 一个**确定性门禁函数** `assessConfidence` 综合（Verifier 不否 × 回归通过 × 改动局部 × 类型通过）判定 high/low，`canAutoApply` 是硬布尔合取。**AI 不持有门禁**——回归失败/Verifier 否决任一成立 → tier=low、永不 canAutoApply，无论 AI 自报多高。
- **有益效果**：SWE-bench Pro 企业全自动 MR <18% 的现实下，给出"可自动 + 可拦截"的安全分级；幻觉无法绕过门禁。
- **权利要求要点**：① AI 输出与确定性门禁的分层；② 硬布尔合取的自动应用判定；③ 回归/Verifier 否决的不可逾越阻断。

## 亮点 3 ★ 运行时数据溯源 DAG（Runtime Data-Provenance DAG）

**简历一句话**：运行时污点追踪构建"DOM 节点 ← JS 函数 ← 接口字段 ← 后端 span"的有向无环图，反向 BFS 把"屏幕上这个错值"确定性地溯源到后端 span，不依赖 LLM。

**专利结构**
- **背景**：前端报错"这个值错了"，定位它来自哪个接口字段、哪个后端 span，业界靠人肉。
- **现有不足**：静态分析做不到运行时数据流；APM 只有关联 trace，无"值→字段→span"的细粒度溯源。
- **本方案**：运行时拦截 fetch/XHR response → 标记字段 → 追踪 JS 消费 → DOM 写入，构建溯源 DAG（`@monit/provenance`）。`traceFrom(domNode)` 反向 BFS 回溯到 span 根。作为 `AttributionRecord.provenanceNode` 接入根因，**确定性**串联前后端（这一段不需 LLM）。
- **有益效果**：把"症状→后端根因"链路的一段做成确定性可溯源；diff 于业界纯关联。
- **权利要求要点**：① 运行时字段级污点→DOM 的 DAG 构建；② 反向 BFS 溯源到 span；③ 与归因候选链的接合点。

## 亮点 4 ★ 自愈防污染护栏（Self-heal Contamination & Test-Sufficiency Guardrail）

**简历一句话**：针对 SWE-bench"通过测试≠真修复"的假阳性，在补丁合入前做"测试充分性评估 + gold-patch 污染检测"双护栏，不足/疑似污染则降级为草稿 PR 转人工。

**专利结构**
- **背景**：SWE-bench Verified ~24% 假阳性根因 = 测试不足（narrow/wide）+ 数据污染（全前沿模型逐字复现 gold patch）；OpenAI 已弃用该基准。
- **现有不足**：自动修 PR 管线普遍只跑现有测试，不评估测试是否"足够"，也不检测污染。
- **本方案**：合入前两道确定性护栏——① `assessTestSufficiency`：AST 启发式判断被改函数是否被测试覆盖（UTBoost 思路）；② `detectContamination`：规范化 + token Jaccard 检测补丁是否逐字/近似复现回归集 gold patch。任一不过 → PR 标记 draft + 转人工，**永不自动合入**。
- **有益效果**：直接针对 SWE-bench 两大假阳性源；前瞻迁移到 SWE-bench Pro / 自建回归集 + contamination auditor。
- **权利要求要点**：① 合入前测试充分性启发式评估；② gold-patch 污染的 verbatim+近重复检测；③ 护栏与信心门禁的级联降级。

## 亮点 5 ★ 显式否决真因果的关联型根因（Correlation RCA with Documented SCM Rejection）

**简历一句话**：基于调研实证，显式选择"变更关联 + 拓扑感知"的关联型 RCA，并**文档化否决**深度因果推断（SCM/do-calculus）——一个有数据支撑的工程决策（Datadog Watchdog / Dynatrace Davis 同样不用 SCM）。

**专利结构**
- **背景**：MTTR 杀手是"最近什么变了"，但学界推 SCM/do-calculus 因果推断。
- **现有不足**：SCM 在生产无量化优越性证据（调研中"SCM 提升精度"强断言被否决）；厂商（Datadog/Dynatrace）营销"causal"实为关联。
- **本方案**：`correlateChange` 做部署/AB/依赖变更 × 异常激增 的时序/版本关联，置信度**封顶 0.7**（关联≠因果，留余地），与确定性规则候选并列排序。文档化否决 SCM 的理由（证据不足 + 生产不适用）。
- **有益效果**：MTTR 显著下降且不引入 SCM 的复杂度/脆弱性；可防御的选型。
- **权利要求要点**：① 变更×异常的时序/版本关联打分（封顶）；② 关联候选与确定性候选的统一排序；③ 显式排除 SCM 的工程范式。

## 简历 bullet 版（可直接用）

- 设计**确定性×AI 混合自愈平台**：独创"注入前反事实对抗验证"（Verifier agent 证伪根因）+ 确定性信心门禁（AI 不做最终门禁），对标 2026 图+LLM+对抗验证 SOTA（F1 88.4%），针对 SWE-bench ~24% 假阳性设计测试充分性 + 污染检测双护栏。
- 构建端到端可观测主链：Web Vitals+LoAF / 6 类错误（双维指纹聚合）/ 请求监控 / 面包屑 / W3C traceparent 透传 / IndexedDB 离线重试 / gzip / 两阶段采样 / PII 脱敏——152 测试，真实浏览器验证上报。
- 运行时数据溯源 DAG：把"屏幕错值 ← 接口字段 ← 后端 span"确定性串联，反向 BFS 溯源，作为根因候选的确定性增强。
- 显式否决 SCM 的关联型根因（变更关联，封顶 0.7），基于行业调研的可防御选型；差异火焰图做性能回归。

## 专利申报建议

5 个亮点中 **亮点 1（注入前对抗验证）** 与 **亮点 2（确定性凌驾 AI 门禁）** 最具新颖性/非显而易见性，建议优先申报（方法权利要求 + 系统权利要求）。亮点 3（溯源 DAG）、4（防污染护栏）可作为从属或独立专利。亮点 5 更适合作为"技术选型白皮书"而非专利。
