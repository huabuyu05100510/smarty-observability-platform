## 独立对抗的价值实证（为什么必须跨 provider）

同一 bug 跑了多组真实对照，证明独立 Verifier 做了**同模型 Verifier 做不到**的事：

| Verifier 配置 | 行为 | 结论 |
|---|---|---|
| 同模型 ARK（doubao 自验证 doubao） | 对"过度泛化"诊断（顺手改了堆栈未涉及的 `renderCount`）**放行** refuted=false conf=1.0 | 同模型 Verifier 与 Diagnoser 相关性同错，rubber-stamp |
| **跨 provider MiniMax（未校准）** | 对"过度泛化"诊断**全部否决** refuted=true conf=0.9，理由正确（"堆栈只含 renderList，改 renderCount 无证据支撑"） | **独立 Verifier 抓住了同模型漏掉的过度泛化** |
| 跨 provider MiniMax（校准后） | 对正确的窄补丁**接受** conf=0.95；对 2-hunk 非局部补丁触发 GateVector → `human` | 独立 + 校准后既不漏判也不过度拦截，门禁按局部性正确分流 |

> 这正是调研结论（Waterloo RF-01：LLM-RCA 头号失败模式是幻觉类比/编造证据）的实证：
> **对抗式 Verifier 必须独立（跨 provider > 跨模型 > 同模型），否则形同虚设。** 本平台用 ARK+MiniMax 跨 provider 做到了。

## GateVector 门禁（BP-4，确定性布尔向量，替加权 score）

交付档位 = 显式向量匹配（AI 不持有门禁）：

```json
{
  "verifier": "pass",            // 跨 provider 独立模型
  "reproRedBefore": true,        // 复现测试未打补丁时失败（证明复现有效，根治"窄测试"假阳性）
  "reproGreenAfter": true,       // 打补丁后通过
  "suiteGreen": true,            // 现有套件不破
  "typecheck": true,
  "locality": { "files": 1, "lines": 3 },   // ≤ 1/50 才 auto-MR
  "contamination": "clean",      // 真实 goldPatch 集检测
  "behaviorPreserving": false
}
// auto-MR = verifier=pass & reproRedBefore & reproGreenAfter & suiteGreen & typecheck & locality.ok & contamination=clean
```

非局部（2 文件）/ 污染命中 / 回归失败 / Verifier 否决 = **永不自动**，转人工（见上表第 3 行真实演示）。

## 单漏斗（BP-1，合并旧双轨）

```
diagnose(runLlmRca) → verify(跨provider独立) → genReproTest → [repro 须先红]
→ applyLocal(searchCode 校验 + replacer 防 $ 注入) → regression(repro 红转绿 + 套件不破 + 3-replay)
→ guardrails(contamination 真实 goldPatch) → GateVector → [auto-mr | hotfix | human]
```

旧 `runHarness`（轨道A）与 `runMrDraftTrack`（轨道B）各拿一半护栏的结构性裂缝已消除：所有补丁必经同一漏斗，hotfix/MR/human 是末端交付路由。

## repro 红转绿（BP-3，根治"通过测试 ≠ 真修复"）

LLM 生成的复现测试 `src/renderList.repro.test.js`：
- 未打补丁（buggy `items.map`）：`renderList(null)` 抛 TypeError → **测试 FAIL（red）**，证明复现有效。
- 打补丁（`(items||[]).map`）：返回 `[]` → **测试 PASS（green）**。

3-replay 多数投票 + repro 由红转绿 = 经验层 + 逻辑层双护栏。SWE-bench 式"窄测试放行错误补丁"在此被堵死（复现测试把 bug 编码进断言）。
