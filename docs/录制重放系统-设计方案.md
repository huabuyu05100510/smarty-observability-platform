# 录制重放系统 · 设计方案

**Record & Replay for Web Performance Bugs** — Vitals Copilot 的确定性场景录制-重放子系统

> 状态:RFC(设计稿,待实现)
> 场景包 schema:`vc-rec/1`
> 关联:本系统同时是「闭环自愈 agent」的**验证地基**(见 §12)

---

## 0. TL;DR

一个针对**性能/错误 bug** 的确定性场景录制-重放系统:**录一次页面交互,产出一个自包含"场景包",对方导入即可在相同操作 + 相同网络 + 相同时序下复现 bug**,而非"看着像"。

- **双范式融合**:同一份录制,既能纯本地视觉回放(rrweb 模式),又能转 Playwright trace 执行复现(真跑 JS、可断言、进 CI)。
- **local-first**:录制、存储、回放全在浏览器本地,零后端,不破坏 Vitals Copilot 定位。
- **性能叠加(独有)**:操作流与 web-vital(INP/LCP/FCP/CLS)+ 错误 + source-map 还原挂在**同一时间轴**,这是通用 session-replay 工具没有的。
- **双重身份**:对用户是 bug 复现分享;对 agent 是 patch 前后对比的**确定性测试床**。

---

## 1. 愿景与定位

### 1.1 问题

前端 bug 大多在**真实用户环境**才暴露,但"我这边复现不了"是协作中最常见的死结。现有手段各有硬伤:

- **视频/Loom**:只能看,不能交互验证。
- **rrweb / LogRocket / Sentry Replay**:视觉重放,**JS 不真跑**,bug 根因(某次特定网络响应、某次时序)常常触发不了——是"重放(replay)"不是"复现(reproduce)"。
- **Playwright codegen**:录操作脚本,但不固化网络/时间/状态,依赖被测页面可达且后端数据一致。

没有任何工具专门为**性能/错误 bug** 做"操作 + 网络 + 时序 + web vital + sourcemap"一体的确定性固化。

### 1.2 定位(无人交集)

> **Record & Replay for Web Performance Bugs** — local-first、双模式、内置 web-vital/sourcemap 层、内置脱敏与 CI、可作为 agent 验证床。

| 维度 | rrweb | Playwright | Sentry/LogRocket | **本系统** |
|---|---|---|---|---|
| 视觉重放 | ✅ | ❌ | ✅ | ✅ |
| 执行复现(真跑) | ❌ | ✅ | ❌ | ✅ |
| 网络固化 | ❌ | 需配 | ✅(后端) | ✅(本地 MSW) |
| 时钟/随机固化 | ❌ | `page.clock` | ❌ | ✅ |
| web vital 叠加 | ❌ | ❌ | 部分 | ✅ |
| source-map 还原 | ❌ | ❌ | ✅(后端) | ✅(本地) |
| local-first/零后端 | ✅ | ✅ | ❌ | ✅ |

## 2. 目标 / 非目标

### 目标
- **确定性复现**:钉死时间、随机、网络、存储、环境五类非确定性来源,使 bug 在回放端稳定触发。
- **自包含场景包**:一个 zip,内含一切(含独立回放器 HTML),对方无需装扩展即可回放。
- **双模式**:视觉回放(秒开、跨环境)+ 执行复现(真跑、可断言、进 CI)。
- **隐私内置**:录制时同步脱敏,PII 永不落盘。

### 非目标(明确不做)
- 不做商业 session-replay 的产品分析(漏斗/热图/用户画像)。
- 不做需要后端的聚合——保持 local-first。
- 不追求"像素级 100% 一致"(受 GPU/字体/视口物理差异限制);目标是**bug 行为可复现**。

---

## 3. 核心论点:双范式融合

录制-重放有两种根本范式,各自只解决一半问题。**最佳实践是录一次、产两种回放。**

### 范式 A · 事件录制 + DOM 增量重放(rrweb 系)
- **录**:初始 DOM 快照 + MutationObserver 增量 + 输入/交互事件 + (本系统扩展)网络/时钟/随机/存储。
- **放**:在隔离 iframe 里重建 DOM,按时序重放 mutation。**JS 不真跑**。
- **优点**:轻(几 KB/s)、快、跨环境、易分享、纯本地。
- **局限**:不是真复现——JS 状态不重建,bug 根因可能不触发。

### 范式 B · 操作录制 + 执行重放(Playwright 系)
- **录**:操作序列(可生成脚本)。
- **放**:在真实浏览器重跑操作,JS **真跑**,网络/时钟用 mock。
- **优点**:真复现、可调试(Inspector)、可断言、能进 CI。
- **局限**:需真实浏览器跑;环境差异仍影响;录制产物较重。

### 融合
一次录制,产出同时支持:
- `replay-visual.html` —— 独立视觉回放器(范式 A,本地双击即看)。
- `replay-exec/trace.zip` —— Playwright trace(范式 B,`show-trace` 执行复现)。

**关键术语诚实**:**重放(replay)** = 看现象;**复现(reproduce)** = 真跑。文档与 UI 必须分清,不用"复现"卖"视觉重放"。

## 4. 非确定性来源清单 + 钉法

"无差异复现"= 把页面所有**非确定性输入**冻住。九类,逐项钉死:

| # | 类别 | 录制 | 回放钉法 | 漏掉的后果 |
|---|---|---|---|---|
| 1 | **DOM 状态** | 初始快照 + MutationObserver 增量 + input 值 + selection + media currentTime | replayer 按时序应用 mutation | 视觉错乱 |
| 2 | **用户交互** | mouse/touch/pointer 轨迹、keyboard(含 IME composition)、wheel、focus/blur、drag,每事件带**精确时间戳** | 按时间戳驱动 | 操作不可复现 |
| 3 | **网络** | fetch/XHR 的 req-resp 对、**WebSocket 帧**、SSE | 回放拦截返回录响应(MSW / SW) | 数据相关 bug 全废 |
| 4 | **时间** | `Date.now`、`performance.now`、`setTimeout/Interval`、rAF、microtask 调度 | **虚拟时钟**,按录时间戳推进 | INP/竞态类全废 |
| 5 | **随机** | `Math.random`、`crypto.getRandomValues` 序列 | 注入录序列 / seeded PRNG | A/B、随机 bug 全废 |
| 6 | **存储** | localStorage / sessionStorage / IndexedDB / cookie **初始快照** | 回放前注入 | 登录态/缓存相关 bug |
| 7 | **环境** | UA、浏览器版本、视口、DPR、时区、语言、字体、GPU、feature-detect、第三方脚本版本 | 写入 meta;回放环境对齐或提示差异 | 渲染时序/特性 bug |
| 8 | **错误/性能** | `error`/`unhandledrejection`、PerformanceObserver 全信号 | 与操作流同时间轴叠加 | (本系统独有增强) |
| 9 | **执行 trace**(可选高阶) | 浏览器底层执行记录 | 时间旅行调试 | 仅最难竞态 bug 需要 |

少钉任何一行,对应类别的 bug 就不可复现。

## 5. 系统架构

```
┌─ 录制层 (content script, isolated world) ──────────────────────────┐
│  rrweb record ─── DOM 快照 + mutation + 交互                        │
│  网络 shim ────── fetch/XHR/WS/SSE 代理,录 req-resp                 │
│  时钟 shim ────── Date.now/perf.now/setTimeout/rAF 录时间戳         │
│  随机 shim ────── Math.random/crypto 录序列                         │
│  存储 snapshot ── localStorage/sessionStorage/IDB/cookie            │
│  脱敏层(同步)── maskAllInputs + maskTextFn + 正则(邮箱/手机/卡)   │
│  ★ 复用 Vitals Copilot 既有采集:错误 + INP/LCP/FCP/CLS/LoAF       │
│  环境探测 ─────── UA/视口/DPR/时区/字体/GPU/3p 版本                  │
└──────────────────────────┬─────────────────────────────────────────┘
                           ▼
┌─ 存储层 (扩展 origin IndexedDB) ───────────────────────────────────┐
│  recordings store(复用 db.js):每个 recording = 一个场景包         │
└──────────────────────────┬─────────────────────────────────────────┘
                           ▼
┌─ 导出层 ──────────────────────────────────────────────────────────┐
│  scenario-{id}.zip(manifest + meta + dom + network + clock +        │
│  storage + signals + sourcemap + replay-visual.html + replay-exec/) │
│  schema 版本化:`vc-rec/1`                                          │
└──────────────────────────┬─────────────────────────────────────────┘
                           ▼
┌─ 回放层 (独立 + 扩展内) ──────────────────────────────────────────┐
│  视觉回放器:rrweb-player + ★ 性能/错误时间轴叠加 + diff 模式        │
│  执行回放器:Playwright trace + MSW handler + page.clock + seeded   │
└──────────────────────────┬─────────────────────────────────────────┘
                           ▼
┌─ agent 接口 (验证床) ─────────────────────────────────────────────┐
│  场景包 = patch 前后对比的确定性测试床:                            │
│  注入 patch → 在场景上执行重放 → 对比 INP/错误 → 保留/回滚          │
└────────────────────────────────────────────────────────────────────┘
```

## 6. 技术选型(不妥协,但不造重复轮子)

| 能力 | 选型 | 理由 |
|---|---|---|
| DOM/交互录制 | **rrweb** | DOM 序列化(Shadow DOM/iframe/canvas/样式/编码/mutation 边界)是几万行血泪,已踩平。MIT、活跃。 |
| 网络录回 | **MSW 2.x** | browser+node 同一套 handler,比 Polly.js 现代、维护活跃。 |
| 执行回放 | **Playwright Trace** | `--trace on` → `trace.zip` → `show-trace`,含 DOM 快照+网络+控制台+源码,生态最成熟。 |
| 时间 mock | 执行回放 `page.clock`;视觉回放 rrweb 内置 timer | — |
| 随机固定 | seeded PRNG(seedrandom)或录序列注入 | — |
| 脱敏 | **自写层**挂到 rrweb `maskAllInputs`/`maskTextFn`/`maskInputFn` | 脱敏是产品决策,不能交默认值。 |
| 时间旅行(高阶可选) | replay.io | 真执行级,最重,仅最难复现竞态用。 |

**该自己写的**:脱敏规则、时钟/随机 shim 的录制-注入对称、场景包 schema、双模式回放器外壳、与 web-vital 的时间轴对齐、agent 验证床接口。

**不该自己写的**:DOM 录制、网络拦截、浏览器自动化——这三样自写等于自杀。

## 7. 场景包 Schema(`vc-rec/1`)

```
scenario-{id}.zip
├── manifest.json        # { schema:"vc-rec/1", recordedAt, durationMs, origin, extVersion, redacted:true }
├── meta.json            # UA/viewport/DPR/timezone/lang/fonts/GPU/feature-detect/3p-versions
├── dom/
│   ├── snapshot.html    # 初始 DOM(rrweb 全量序列化,已脱敏)
│   └── events.jsonl     # mutation + 交互增量(rrweb events,brotli 压缩)
├── network/
│   ├── http.jsonl       # fetch/XHR req-resp 对(已脱敏 headers/body)
│   ├── ws.jsonl         # WebSocket 帧
│   └── sse.jsonl
├── clock.json           # 时间戳序列 + random 序列(虚拟时钟种子)
├── storage.json         # localStorage/sessionStorage/cookie/IndexedDB 快照(已脱敏)
├── signals.jsonl        # ★ 错误 + INP/LCP/FCP/CLS/LoAF 事件流,带时间戳(本系统独有)
├── sourcemap/           # ★ 错误栈已还原的 resolvedFrames + sourcesContent 片段
├── replay-visual.html   # 独立视觉回放器(本地双击即看,零依赖)
└── replay-exec/
    └── trace.zip        # Playwright trace(可 show-trace 执行复现)
```

**版本化契约**:`manifest.schema` 字段;旧包必须能被新回放器读(major 版本兼容策略)。这是开源项目让别人能写工具消费本格式的前提。

带 ★ 的是相对 rrweb/Playwright 的差异化层。

## 8. 开源级非功能要求(全部必须)

这些是把"能跑的 demo"和"可开源代表作"分开的线,不是可选:

1. **隐私脱敏(内置、录制时同步)**:密码框、hidden input、Authorization/cookie header、邮箱/手机/身份证/卡号正则。**必须录制时脱敏**,后置可能已泄漏。可配置白名单(某 origin 不脱敏某字段)。`manifest.redacted: true` 标注已脱敏。
2. **场景包版本化 schema**:`vc-rec/N`,向前兼容。
3. **独立回放器**:`replay-visual.html` 纯本地、零后端、零依赖,双击即看。闭源回放器 = 信任崩塌。
4. **压缩**:events → brotli/gzip。长录制不压缩会爆 IDB。
5. **时间轴统一对齐**:操作 / 网络 / 错误 / 性能挂同一时间轴,回放器可同步游标(本系统独有视图)。
6. **diff 模式**:录两次(正常 vs bug),逐帧 diff DOM/网络/事件,定位分歧起点。
7. **CI 集成**:场景包 → Playwright 测试 + 断言("应无错误"/"INP < N"),防回归。
8. **同意机制**:扩展录制需用户显式触发 + 明确知情提示(Chrome 商店审核硬要求)。

## 9. 安全与隐私

- **录制范围最小化**:默认仅录用户触发,不后台静默录。
- **脱敏不可关闭默认**:可在设置里为信任 origin 放宽,但全局默认开。
- **本地存储**:录制物仅在扩展 origin IndexedDB,导出是用户主动动作。
- **分享警示**:导出前 UI 明确提示"即使已脱敏,网络响应可能含业务敏感数据,请确认分享对象"。
- **CSP 兼容**:录制 shim 在 isolated world 注入,不破坏页面 CSP;回放器在扩展 origin。

---

## 10. 必须避开的坑

- **不要自己写 DOM 录制**(用 rrweb)。
- **术语诚实**:重放 ≠ 复现,文档/UI 分清。
- **脱敏不能后置**(同步做)。
- **不能漏时间/随机**(否则 INP/竞态 bug 全不可复现)。
- **回放器不能依赖后端**(纯本地)。
- **schema 必须版本化**(否则升级即破)。
- **执行回放的环境漂移**:第三方 CDN 版本、GPU/字体差异会在 meta 里钉版本,回放时提示。

---

## 11. 实现路线(按依赖顺序,不剪裁功能)

每步都到位,没有"先 MVP 后补"。区别只是按依赖推进,不是砍掉后半段:

1. **录制核心**:rrweb 集成 + 网络录(fetch/XHR/WS shim)+ 时钟/随机/存储 shim + **脱敏层(同步)** + 复用既有错误/性能采集接入时间轴。
2. **存储 + 场景包 schema**:IndexedDB `recordings` store + manifest/version + 导出 zip + 独立 `replay-visual.html`。
3. **视觉回放器**:rrweb-player + 性能/错误时间轴叠加 + diff 模式 + 同意/隐私提示。
4. **执行回放器**:导出 Playwright trace + MSW handler + `page.clock` + seeded random → `show-trace` 真复现。
5. **CI 集成**:trace → Playwright 测试 + 断言,防回归。
6. **agent 验证床**:场景包作为 patch 前后对比的测试床(接闭环自愈)。
7. **高阶模式(可选)**:replay.io 接入,执行级时间旅行。

## 12. 与代表作的集成(agent 验证床)

本系统不是孤立工具——它是 Vitals Copilot「local-first autonomous remediation agent」的**验证地基**。

闭环自愈 agent 要回答"patch 后 INP 是否真降",必须在**同一可重复交互序列**上测前后。**没有 deterministic replay,就没有可信的测量验证**——单次 INP 数字下降可能是噪声。

```
归因(感知) → 候选 patch 生成 → 在场景包上执行重放(验证) → 统计显著性判定 → 保留/回滚 → 沉淀知识库
                         ↑                                      ↓
                         └──────────── 场景包(deterministic) ──┘
```

场景包把"验证"从"一次看运气"变成"可重复测量的实验"。这是 agent 可信度的质变,也是相对其它"生成 patch 就完事"的 agent 项目的核心护城河。

## 13. 开放问题

- **后端真状态**:MSW 录的是历史响应;若 bug 依赖后端实时计算/写入,只能逼近。是否提供"录制时同时打后端快照(可选)"?
- **Canvas / WebGL**:rrweb 对 canvas 默认录截图,体积大;是否提供"录绘制指令"模式?
- **跨域 iframe**:受同源策略限制,只能录顶层;文档需明确边界。
- **执行回放的环境一致性**:Playwright 跑在 Chromium;Firefox/Safari 录制如何执行复现?需限定"执行复现仅保证 Chromium"。
- **体积治理**:长录制(>10min)即使压缩也大;是否提供"按需分段 + 关键区间"裁剪(用户显式,不静默丢)?
