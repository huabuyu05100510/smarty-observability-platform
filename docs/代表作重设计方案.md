# smarty-observability-platform · 代表作级重设计方案

> 目标：把现有项目从"宽度够、密度不够"升级为 **14 年专家代表作**。
> 四支柱（性能/错误/白屏/行为）各自极致深度、均为头号亮点；自愈做成**极致闭环**；
> 每条主张都有**真实跑通的路径**支撑，以**能力矩阵**如实标注实现度。代表作级 ≠ demo。

---

## 0. 代表作硬标准（四把尺子）

1. **单漏斗完整性**：头条论点（自愈闭环）在一根真实路径上凑齐全部门禁。
2. **校准诚实**：删未校准魔法数字、删被 wiring 静默卸掉的护栏；占位启发式不得当硬门禁。
3. **关键路径真实跑通**：头号动机（跨层 trace join）做实；至少一次真实外部联调留痕（真浏览器+真 LLM+真 PR）。
4. **可防御的新颖性**：prior art / 我的贡献 / 校准状态三列分清，主打亮点收敛到可防御的少数几个。

**保留的地基（不动）**：contracts 信封模型、trace propagator（W3C）、fingerprint 双维、reporter 传输（keepalive+离线+gzip）、vitals/LoAF 采集、replay 录制、errors 6 类采集、coordinator github-pr 防御性回退。

## 1. 总体架构（统一）

```
┌─ L6 极致闭环  runHealPipeline（单漏斗，合并旧 runHarness+runMrDraftTrack）─────────┐
│  diagnose(runLlmRca) → verify(独立模型) → genReproTest(须先红) → applyLocal        │
│   → regression(repro 红转绿+套件不破) → guardrails → gateVector → [hotfix|MR|human]│
├─ L4 四支柱归因  @monit/diagnose（性能含跨层trace / 错误 / 白屏 / 行为 多源候选链）──┤
├─ L3 数据面  @monit/backend（event+span+白屏+行为索引 / 聚合 / sourcemap / 面板）───┤
├─ L2 统一上下文  @monit/contracts（信封+Span+GateVector+ReproTest+…）              │
│                 @monit/trace（W3C traceparent，per-event span，软导航 startView） │
├─ L1 采集  @monit/collector（vitals+LoAF / 6类错误 / 白屏检测 / 行为沮丧 / replay） │
└──────────────────────────────────────────────────────────────────────────────────┘
```

两个关键架构动作：
- **合并双轨为单漏斗** `runHealPipeline`：hotfix/MR/human 是漏斗末端的**交付路由**，不再各拿一半护栏。
- **做实跨层 trace join**：collector 注 traceparent → demo backend 为 API 请求产 span（同 traceId）→ diagnose 用 traceId 查同 trace 慢 span → `AttributionRecord.traceId` 真填。

## 2. 四支柱极致深度

### 2.1 性能（含 tracing，头号亮点·皇冠=跨层 join）
现状：vitals/LoAF/火焰图已有；缺 LCP 归因、软导航、跨层 join、回归检测。
- **LCP 归因**：element + url + TTFB/资源加载/渲染延迟拆解（不只给值，给"为什么慢"）。
- **软导航**：SPA 路由切换触发 `startView()` 重置 trace + per-route vitals。
- **跨层 trace join（皇冠）**：collector 注 traceparent → backend 摄入 API 请求 span（同 traceId，含服务端处理时长）→ diagnose 用 error/vital.traceId join 同 trace 慢 backend span → 产 `kind='dependency'` candidate 指向 span，`AttributionRecord.traceId` 真填。这是多数可观测工具在吹却没做的，做实即最强卖点。
- **LoAF charPosition 归因**：diagnose 已到脚本级，补 charPosition 上下文片段。
- **自动性能回归检测**：baseline + diff flamegraph + 统计阈值（非"感觉变慢"）。
- **per-route/release/cohort p75/p99**（store 已有 p75/p99，补维度切分）。

### 2.2 错误
现状：6 类采集+指纹+分组+sourcemap(backend 真实) 已好；AI 诊断 crude（`===DIAGNOSIS===` 正则）。
- **智能分组**：栈帧归一化、跨 message 去重（不只 primary 指纹硬等）。
- **release 回归关联**：错误首发于哪个 release（store 加 firstRelease）。
- **sourcemap 统一**：删 repair-agent 的 stub resolver，全平台走 backend 真实 `source-map` 还原。
- **AI 诊断升级**：`runAiDiagnosis` 改调 `runLlmRca` 多 agent（Navigator/Diagnoser/Verifier），替掉正则解析。
- **错误率 spike 检测**（已有 trend，加 spike 判定）。

### 2.3 白屏（现状最弱：契约有信号、无检测器、无归因）
- **collector 白屏检测器**：采样点 9/17/33 比率 + DOM 空判 + 关键资源 404 判 + FCP 超时判。
- **白屏类型分类**：blank DOM / crashed render / critical resource blocked / route 404。
- **因果归因**：按时序关联**触发白屏的具体** error/resource（非笼统 recentErrors），产 `kind='white_screen'` candidate。
- **恢复建议**：接入 heal 白名单（critical resource 降级/fallback）。

### 2.4 行为
现状：session-replay 录制 + breadcrumbs 已好；缺沮丧信号、旅程、时间轴对齐。
- **沮丧信号**：rage click / dead click / erratic mouse / 重复报错 / frustrated nav → 新 `type='behavior'` 事件。
- **用户旅程时间线**：路由切换 + 事件锚点串成 timeline。
- **replay × error/vital 时间轴对齐**：scrub 到错误/vital 瞬间。
- **行为索引**：backend 按会话聚合沮丧信号数。

## 3. 极致闭环：单漏斗自愈管线 `runHealPipeline`

合并旧 `runHarness` + `runMrDraftTrack`，所有补丁必经：

```
1. diagnose      — runLlmRca 多 agent（结构化上下文，非原始遥测）
2. verify        — 独立模型 Verifier（BP-2）：refuted → altHypothesis 回喂重诊断，不注入
3. genReproTest  — LLM 生成复现 bug 的失败测试；必须先在【未打补丁】代码上 FAIL（证明复现有效），否则回炉
4. applyLocal    — searchCode 真实存在校验 + apply（replacer 函数防 $ 特殊模式；targetPath JSON.stringify 防注入）
5. regression    — repro 由红转绿 + 现有套件不破 + 3-replay 防抖（repro 编码了 bug，根治"窄测试"假阳性）
6. guardrails    — test-sufficiency 由 repro 替代字符串启发式 + contamination 用真实 goldPatch 集
7. gateVector    — 布尔向量判定（非加权 score），见下
8. delivery      — hotfix(patch-registry-over-SDK+真rollback) | MR(createGithubPr) | human
```

**GateVector（替掉 assessConfidence 加权 score，消灭伪精度）**：
```ts
type GateVector = {
  verifier: 'pass' | 'refuted' | 'skipped';   // 独立模型
  reproRedBefore: boolean;    // 未打补丁时复现测试失败（证明测试有效）
  reproGreenAfter: boolean;   // 打补丁后通过
  suiteGreen: boolean;        // 现有套件不破
  typecheck: boolean;
  locality: { files: number; lines: number }; // ≤1 文件 / ≤50 行
  contamination: 'clean' | 'detected';
  behaviorPreserving: boolean; // 热修专用：非 masking
};
// 交付档位 = 显式向量匹配：
//   auto-MR : verifier=pass & reproRedBefore & reproGreenAfter & suiteGreen & typecheck & locality.ok & contamination=clean
//   hotfix  : verifier=pass & reproGreenAfter & behaviorPreserving（可逆）
//   human   : 任一不满足 → 永不自动
```

**Verifier 独立模型**：Diagnoser=`doubao-seed-2-0-code-preview`（code 模型），Verifier=同 ARK key 换**不同 doubao model id**（通用/推理模型）。配置层强制 `verifier.model !== diagnoser.model`，同则降级标 `verifier='skipped'` 并降档。诚实标注：同 provider 不同 model = 部分独立（强于同模型，弱于跨 provider）。

**热修轨道改造**：删 `prototype` patch（全局破坏性）；`error-boundary` 改标 `masking`（非 fix，且不压遥测）；patch 返回 `{rollback:()=>void}` 真恢复；交付改 **patch-registry-over-SDK**（签名 patch 下推，SDK 按指纹应用），非 CDP（生产不可达）。`/heal/apply` 不再 stub，真调 `runHealPipeline` 轨道 A。

## 8. 风险/取舍

- 工作量周级，分阶段交付，每阶段独立可验证（不一次性 big-bang）。
- 独立模型仅同 provider 不同 model（诚实标注，非跨 provider 独立）。
- 留痕会向 test repo 真开 PR（已确认）+ 少量 ARK 额度。
- 若某"极致深度"项（如统计显著回归检测）超当前 scope，在矩阵标 `designed` 而非谎称完成。
